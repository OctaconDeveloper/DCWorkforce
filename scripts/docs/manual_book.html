Part I: System Overview & Permissions

1. System Architecture & Objectives

The DC Kubwa Workforce Management System is an automated enterprise bot infrastructure designed to streamline church workforce communications, member records, duty rosters, approval workflows, and broadcast notifications.

1

Database & Profiles

Tracks active workers, department/unit assignments, marital status, and leadership credentials (HOD/Unit Head/Admin).

2

Media Broadcast Engine

Dispatches text, photos, PDFs & voice notes to units, departments, church-wide, or custom groups.

3

Member Search

Provides fast, case-insensitive search by Name, Phone, Unit, Department, or Role within leadership boundaries.

4

Data Protection

Prevents duplicate registrations by phone number and manages moderation queues.

4. Strict Duplicate Registration Rejection

When a user submits a worker registration form, the system performs validation checks to eliminate duplicate entries:

  • Active Worker Match: If the submitted phone number already belongs to an active church worker, the registration is instantly rejected, showing the existing worker's name, department, unit, and role.
  • Pending Application Match: If a registration request for that phone number is already pending review with an HOD, the applicant is notified of their pending status.
🟢 WhatsApp • Duplicate Registration Rejection
❌ *REGISTRATION REJECTED: PHONE ALREADY REGISTERED* ──────────────────────────── A church worker record already exists with the phone number *08012345678*: • *Full Name:* Brother David Eze • *Department:* MEDIA (Sound) • *Role:* Member • *Status:* Active ✅ 💡 *Note:* If you need to update your details or change departments, please contact your Head of Department (HOD) or Church Administrator. _Type *menu* to return to the main menu._

Part III: Multi-Target Broadcast Engine

6. Text & Media Broadcast System

The workforce bot contains a broadcast engine capable of sending plain text, images, flyer documents, audio/voice notes, and video highlights to targeted workforce groups.

Supported Broadcast Scopes:

Broadcast Command Allowed Roles Target Recipients Media Support
broadcast unit <message> Unit Head HOD Admin All active workers in the sender's unit. ✅ Photos, PDFs, Audio, Video
broadcast dept <message> HOD Admin All active workers in the sender's department. ✅ Photos, PDFs, Audio, Video
broadcast all <message> Admin Only Every registered worker across all church departments. ✅ Photos, PDFs, Audio, Video
broadcast group <name> <msg> Admin Only Members enrolled in the specified custom broadcast group. ✅ Photos, PDFs, Audio, Video

How to Broadcast Media (Photos, Flyers, PDFs, Voice Notes):

1

Attach Media

In WhatsApp or Telegram, select the photo, PDF flyer, audio note, or video you wish to broadcast.

2

Set Caption

Write the broadcast command directly in the media caption: broadcast unit Meeting tomorrow by 6 PM.

3

Automatic Dispatch

The bot downloads the media buffer, detects mimetype (image/doc/audio/video), and sends both media and caption to all targeted recipients.

4

Delivery Summary

You receive an instant receipt showing delivered count, failed count, and target group.

🛡️
Enterprise WhatsApp Anti-Ban & Outbound Queue Engine (<3% Ban Risk):
To protect the church's WhatsApp line during peak Sunday attendance spikes, the system routes all outgoing messages through a centralized WhatsAppQueueService:
  • FIFO Priority Queue: Direct 1-on-1 replies receive high priority while mass broadcasts are smoothly serialized at max 20 msgs/min.
  • Humanized Typing Presence: The bot simulates realistic composing (1.2–2.0s) before every message and recording before voice clips.
  • Randomized Jitter Delays: Every outgoing reply pauses for a randomized 3 to 5 seconds (3000ms–5000ms) to match human pacing.
  • Dynamic Pastoral Personalization: Replies dynamically insert worker first names and rotate warm blessings so messages are never flagged as repetitive spam.
  • Link-on-Demand Protection: Public menus and mass broadcasts avoid blast URLs; links are delivered only when the worker explicitly requests them.
  • Session Credentials Backup: Auth session credentials (creds.json) are bundled into the automated nightly backup sent to Media HOD (+2348101889830).

Automated Daily Database Backup (Cron Schedule)

🛡️
Automated Nightly Backup Engine:
The system runs a background cron task every day at 02:00 AM WAT. It automatically packages the entire SQLite database file (.db) along with the WhatsApp authentication credentials (creds.json) and a complete structured JSON record dump, delivering them directly via WhatsApp document message to the primary technical administrator (+2348101889830).

On-Demand Trigger: Authorized administrators and +2348101889830 can also trigger an immediate backup at any time by sending #backup, backup db, or backup database on WhatsApp.
